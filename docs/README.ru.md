# opons-voxd

> Примечание: opons-voxd никак не связан с jakovius/voxd. Название выбрано независимо — `opons` = O. Pons (автор), `voxd` = vox + daemon (латинская и юниксовая традиция).

> **⚠ Обратная совместимость нарушена намеренно.** Раньше проект назывался `voice_in_linux`. При переименовании изменились имя бинарного файла, имя исходного файла и все переменные окружения (`VOICE_IN_*` → `OPONS_VOXD_*`), а зависимость от `xdotool` во время выполнения исчезла: её заменил прямой синтез ввода через XTest (`libxtst-dev`). Никаких псевдонимов, никакого переходного периода — обновите скрипты запуска, записи автозапуска и строки `apt install`.

**Локальная голосовая диктовка для Linux — ваш голос не покидает компьютер.**

## Зачем?

Мне хотелось диктовать текст в любое приложение в Linux, не отправляя свой голос на сторонний сервер. Все готовые решения, которые я нашёл, — расширения для браузера, облачные API, SaaS-платформы — передают звук на удалённые серверы для распознавания. Значит, каждое сказанное вами слово идёт через интернет: письма, конфиденциальные документы, данные клиентов, личные заметки — всё подряд.

Этот проект — лёгкая и полностью локальная альтернатива. Он работает целиком на вашем компьютере и использует [whisper.cpp](https://github.com/ggerganov/whisper.cpp) — реализацию Whisper, открытой модели распознавания речи от OpenAI. После первоначальной настройки сеть не нужна. Никакие данные не покидают ваш компьютер.

Сделано с помощью ИИ.

## Как это работает

Два способа диктовки, доступные одновременно.

### Режим значка в трее — запись по щелчку, текст в буфер обмена

1. В системном трее появляется маленький значок
2. **Щелчок левой кнопкой** → начинается запись (значок становится красным)
3. **Повторный щелчок левой кнопкой** → запись останавливается, звук локально распознаётся через Whisper
4. Распознанный текст автоматически копируется в буфер обмена (в оба выделения X11)
5. Уведомление на рабочем столе показывает текст 10 секунд
6. Вставить текст можно куда угодно: `Ctrl+Shift+V`, `Shift+Insert` или щелчок средней кнопкой

**Щелчок правой кнопкой** по значку открывает меню Toggle / Unload models / Reload models / Quit (см. [Освобождение GPU для локального ИИ](#освобождение-gpu-для-локального-ии-mcp-сервер)).

### Режим push-to-talk — удерживайте горячую клавишу, текст печатается у курсора

1. **Удерживайте `Ctrl+Shift+Space`** → начинается запись (значок становится красным)
2. **Отпустите клавиши** → запись останавливается, звук распознаётся
3. Распознанный текст **печатается прямо в позиции курсора** (через расширение X11 XTest) в том окне, которое находится в фокусе

Горячая клавиша настраивается через `OPONS_VOXD_PTT_HOTKEY`. Вторая, независимая горячая клавиша (`OPONS_VOXD_PTT_TRANSLATE_HOTKEY`, по умолчанию `ctrl+alt+t`) работает так же, но печатает перевод на английский — см. [основной README](../README.md#push-to-talk-and-translate-hotkey).

## Возможности

- **100% локально** — звук обрабатывается на CPU или GPU и никуда не отправляется
- **Ускорение на GPU** — поддержка NVIDIA CUDA для почти мгновенного распознавания
- **99 языков** — на базе OpenAI Whisper
- **Лёгкость** — чистый C, без Python: демон и необязательный MCP-сервер размером 25 КБ, связанный только с libc
- **Интеграция с системным треем** — ненавязчивый значок на панели задач
- **Горячая клавиша push-to-talk** — удерживайте `Ctrl+Shift+Space` (настраивается), чтобы записывать, и отпустите, чтобы распознанный текст напечатался в позиции курсора
- **Горячая клавиша push-to-talk с переводом** — вторая горячая клавиша, настраиваемая отдельно, печатает не дословную расшифровку, а перевод вашей речи на английский
- **Два буфера обмена** — текст попадает в оба выделения X11: PRIMARY и CLIPBOARD
- **Уведомления на рабочем столе** — распознанный текст показывается во всплывающем уведомлении
- **Голосовые команды** — по одному файлу команд на язык в `commands/`, по умолчанию отключены (включаются через `OPONS_VOXD_COMMANDS=1`). Чтобы добавить язык, достаточно создать `commands/xx.txt`, перекомпиляция не нужна.
- **Временные уведомления** — по умолчанию уведомления появляются, а затем исчезают бесследно. `OPONS_VOXD_NOTIFY_PERSIST=1` сохраняет их в истории.
- **Режим уведомлений** — `OPONS_VOXD_NOTIFY=normal|quiet|silent|off` управляет уведомлениями об успехе (по умолчанию `quiet`: всплывающее окно без звука). Ошибки всегда показываются со звуком, в любом режиме, без исключений. Полная таблица — в основном README.
- **Автоматические заглавные буквы** — предложения автоматически начинаются с заглавной буквы
- **Освобождение GPU по запросу** — выгрузите модели Whisper из видеопамяти (через меню в трее или любым ИИ-агентом через встроенный MCP-сервер) и загрузите их снова, когда закончите
- **Автозапуск** — можно настроить запуск при входе в систему

## Требования

### Операционная система

| Требование | Минимум | Проверка |
|---|---|---|
| Ubuntu / Linux Mint | 22.04 / 21 | `lsb_release -a` |
| Ядро Linux | 5.15+ | `uname -r` |
| Графический сервер | X11 | `echo $XDG_SESSION_TYPE` |

> Wayland не поддерживается (GtkStatusIcon требует X11). Linux Mint по умолчанию использует X11.

### Инструменты сборки (обязательно)

| Пакет | Минимум | Установка |
|---|---|---|
| gcc | 9.0+ | `sudo apt install build-essential` |
| cmake | 3.14+ | `sudo apt install cmake` |
| pkg-config | 0.29+ | `sudo apt install pkg-config` |
| git | 2.25+ | `sudo apt install git` |

### Библиотеки для разработки (обязательно)

| Пакет | Минимум | Установка |
|---|---|---|
| libgtk-3-dev | 3.22+ | `sudo apt install libgtk-3-dev` |
| libnotify-dev | 0.7+ | `sudo apt install libnotify-dev` |
| libportaudio2 | 19.6+ | `sudo apt install libportaudio2` |
| libcairo2-dev | 1.14+ | `sudo apt install libcairo2-dev` |
| libx11-dev | 1.6+ | `sudo apt install libx11-dev` |
| libxtst-dev | 1.2+ | `sudo apt install libxtst-dev` |

> `libportaudio-dev` не нужен: сборка сама скачивает `portaudio.h` (через `curl`, при первом `make`) и линкуется напрямую с `libportaudio.so.2`. Подробности — в [основном README](../README.md#development-libraries-required).

### Инструменты времени выполнения (обязательно)

| Инструмент | Назначение | Установка |
|---|---|---|
| xclip | Копирование в буферы обмена X11 | `sudo apt install xclip` |
| notify-send | Уведомления на рабочем столе | `sudo apt install libnotify-bin` |

### Видеокарта NVIDIA (необязательно, но критично для производительности)

Без CUDA обработка 15 секунд речи займёт **10–15 секунд**. С CUDA — **меньше 1 секунды**. Обработка ускоряется **в 10–50 раз**.

| Компонент | Минимум | Проверка |
|---|---|---|
| Драйвер NVIDIA | 570+ | `nvidia-smi` |
| CUDA Toolkit | 12.0+ | `nvcc --version` |

Если `nvidia-smi` работает, а `nvcc` — нет, установите CUDA Toolkit:

```bash
sudo apt install nvidia-cuda-toolkit
```

Если версия CUDA, которую показывает `nvidia-smi`, **ниже** той, что сообщает `nvcc`, обновите драйвер:

```bash
ubuntu-drivers devices
sudo apt install nvidia-driver-590
sudo reboot
```

## Установка

```bash
# 1. Системные зависимости
sudo apt update
sudo apt install -y \
    build-essential cmake pkg-config git curl \
    libgtk-3-dev libnotify-dev libportaudio2 libcairo2-dev libx11-dev libxtst-dev \
    xclip libnotify-bin

# 2. Клонирование репозитория
git clone https://github.com/olivierpons/opons-voxd.git
cd opons-voxd

# 3. Сборка whisper.cpp и загрузка модели
make setup

# 4. Сборка исполняемых файлов: opons-voxd (демон) и opons-voxd-mcp (необязательный MCP-сервер)
make

# 5. Запуск
./opons-voxd
```

## Освобождение GPU для локального ИИ (MCP-сервер)

Модели Whisper всё время находятся в памяти GPU (около 3,8 ГБ для `large-v3-turbo` + `medium`). Когда эта видеопамять нужна для другой задачи — локальной LLM, модели генерации изображений, обучения, — opons-voxd может выгрузить модели и потом загрузить их обратно, не завершая работу. При выгрузке уничтожается и CUDA-контекст процесса, поэтому opons-voxd полностью исчезает из вывода `nvidia-smi` (0 МБ видеопамяти). Повторная загрузка занимает меньше секунды, если файлы моделей ещё в страничном кеше, и несколько секунд, если нет.

**Состояния значка в трее:**

| Значок | Состояние |
|:---:|---|
| белое кольцо | модели загружены, всё готово |
| красный круг | идёт запись |
| оранжевый круг | идёт распознавание |
| серое перечёркнутое кольцо (⊘) | модели выгружены, память GPU освобождена, диктовка отключена |
| синяя дуга в три четверти круга | модели загружаются заново |

Пока модели выгружены, щелчок по значку или нажатие горячей клавиши push-to-talk не запускает запись, а выводит уведомление об ошибке.

**Вручную:** щёлкните правой кнопкой по значку в трее > *Unload models (free GPU memory)* (выгрузить модели), затем *Reload models* (загрузить модели снова).

**Из ИИ-агента (MCP):** запустите демон с `-m` / `--mcp` (по умолчанию выключено). `make` также собирает `opons-voxd-mcp` — сервер [Model Context Protocol](https://modelcontextprotocol.io), работающий через stdio и связанный только с libc (около 1,5 МБ ОЗУ). Он предоставляет три инструмента: `unload_models`, `reload_models` и `get_status`. Для Claude Code:

```bash
claude mcp add --scope user opons-voxd -- /path/to/opons-voxd/opons-voxd-mcp
```

Большинство других клиентов (Claude Desktop, Cursor, LM Studio...) используют такой JSON:

```json
{ "mcpServers": { "opons-voxd": { "command": "/path/to/opons-voxd/opons-voxd-mcp" } } }
```

Подробности — в [основном README](../README.md#free-the-gpu-for-local-ai-mcp-server).

## Горячая клавиша push-to-talk

Поставляемый `launch.sh` использует `ctrl+alt+w` (рекомендуется для AZERTY) или `ctrl+alt+z` (рекомендуется для QWERTY). Эта клавиша находится рядом с `A`, поэтому всё сочетание можно нажать одной левой рукой (мизинец на `Ctrl`, большой палец на `Alt`, безымянный или средний на `W`/`Z`), не меняя положения рук для печати. К тому же в большинстве окружений рабочего стола это сочетание по умолчанию ничем не занято. Горячая клавиша задаётся через `OPONS_VOXD_PTT_HOTKEY`. Подробности — в [основном README](../README.md#push-to-talk-hotkey).

## Стиль кода

Проект следует **стилю кода ядра Linux** (`Documentation/process/coding-style.rst`) с изменениями, которые внёс Olivier Pons: фигурные скобки в стиле K&R, отступ в 4 пробела, `struct name` без typedef, без префиксов (`s_`, `t_`, `e_`), `return value;` без скобок, комментарии kernel-doc, не более 80 символов в строке.
