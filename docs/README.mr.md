# opons-voxd

> टीप: opons-voxd चा jakovius/voxd शी काहीही संबंध नाही. हे नाव स्वतंत्रपणे निवडले आहे — `opons` = O. Pons (लेखक), `voxd` = vox + daemon (लॅटिन/Unix परंपरा).

> **⚠ जुन्या आवृत्त्यांशी सुसंगतता जाणीवपूर्वक मोडली आहे.** हा प्रकल्प आधी `voice_in_linux` या नावाने ओळखला जात असे. नाव बदलल्याचा परिणाम बायनरीचे नाव, सोर्स फाइलचे नाव, प्रत्येक एन्व्हायर्न्मेंट व्हेरिएबल (`VOICE_IN_*` → `OPONS_VOXD_*`) आणि रनटाइमला लागणारी `xdotool` ची गरज यांवर झाला आहे (त्याऐवजी आता `libxtst-dev` द्वारे थेट XTest वापरून इनपुट तयार केले जाते). कोणतेही alias नाहीत, कोणताही संक्रमण काळ नाही — तुमच्या लॉन्च स्क्रिप्ट्स, ऑटोस्टार्ट नोंदी आणि `apt install` च्या ओळी अद्ययावत करा.

**Linux साठी लोकल स्पीच-टू-टेक्स्ट डिक्टेशन — तुमचा आवाज तुमच्या मशीनबाहेर कधीच जात नाही.**

## का?

मला Linux वरील कोणत्याही ॲप्लिकेशनमध्ये बोलून मजकूर लिहायचा होता, तोही माझा आवाज कोणत्याही त्रयस्थ सर्व्हरकडे न पाठवता. मला सापडलेले सगळे उपाय — ब्राउझर एक्स्टेंशन्स, क्लाउड API, SaaS प्लॅटफॉर्म्स — ट्रान्सक्रिप्शनसाठी तुमचा ऑडिओ दूरच्या सर्व्हर्सकडे स्ट्रीम करतात. म्हणजे तुम्ही बोललेला प्रत्येक शब्द इंटरनेटवरून जातो: ईमेल्स, गोपनीय कागदपत्रे, क्लायंटचा डेटा, वैयक्तिक नोंदी — सगळे काही.

हा प्रकल्प एक हलका, पूर्णपणे लोकल पर्याय आहे. तो संपूर्णपणे तुमच्या मशीनवर [whisper.cpp](https://github.com/ggerganov/whisper.cpp) वापरून चालतो; whisper.cpp हे Whisper साठीचे लोकल रनटाइम आहे, आणि Whisper हे OpenAI चे ओपन-सोर्स स्पीच रेकग्निशन मॉडेल आहे. सुरुवातीच्या सेटअपनंतर नेटवर्क कनेक्शनची गरज नसते. कोणताही डेटा तुमच्या संगणकाबाहेर कधीच जात नाही.

हा प्रकल्प AI च्या मदतीने तयार केला आहे.

## हे कसे काम करते

डिक्टेशनचे दोन मार्ग, दोन्ही एकाच वेळी उपलब्ध.

### ट्रे आयकॉन मोड — एका क्लिकने सुरू/बंद, मजकूर क्लिपबोर्डवर

1. तुमच्या सिस्टम ट्रेमध्ये एक छोटा आयकॉन दिसतो
2. **लेफ्ट-क्लिक** → रेकॉर्डिंग सुरू होते (आयकॉन लाल होतो)
3. **पुन्हा लेफ्ट-क्लिक** → रेकॉर्डिंग थांबते, Whisper तुमच्या मशीनवरच ऑडिओचे ट्रान्सक्रिप्शन करते
4. ट्रान्सक्राइब झालेला मजकूर आपोआप तुमच्या क्लिपबोर्डवर कॉपी होतो (X11 च्या दोन्ही सिलेक्शन्समध्ये)
5. डेस्कटॉप नोटिफिकेशनमध्ये तो मजकूर 10 सेकंद दिसतो
6. `Ctrl+Shift+V`, `Shift+Insert` किंवा मिडल-क्लिकने कुठेही पेस्ट करा

आयकॉनवर **राइट-क्लिक** केल्यास एक मेनू उघडतो: Toggle / Unload models / Reload models / Quit ([लोकल AI साठी GPU मोकळा करणे](#लोकल-ai-साठी-gpu-मोकळा-करणे-mcp-सर्व्हर) पहा).

### Push-to-talk मोड — हॉटकी दाबून ठेवणे, कर्सरवर टायपिंग

1. **`Ctrl+Shift+Space` दाबून ठेवा** → रेकॉर्डिंग सुरू होते (आयकॉन लाल होतो)
2. **कीज सोडा** → रेकॉर्डिंग थांबते, ऑडिओचे ट्रान्सक्रिप्शन होते
3. ट्रान्सक्राइब झालेला मजकूर **थेट कीबोर्ड कर्सरवर टाइप होतो** (X11 च्या XTest एक्स्टेंशनद्वारे), ज्या विंडोवर फोकस असेल त्याच विंडोत

हॉटकी `OPONS_VOXD_PTT_HOTKEY` ने बदलता येते. दुसरी, स्वतंत्र हॉटकी (`OPONS_VOXD_PTT_TRANSLATE_HOTKEY`, डिफॉल्ट `ctrl+alt+t`) याच पद्धतीने काम करते, पण ट्रान्सक्रिप्टऐवजी इंग्रजी भाषांतर टाइप करते — [मुख्य README](../README.md#push-to-talk-and-translate-hotkey) पहा.

## वैशिष्ट्ये

- **100% लोकल** — ऑडिओवर तुमच्या CPU किंवा GPU वर प्रक्रिया होते, तो कुठेही पाठवला जात नाही
- **GPU प्रवेग** — जवळजवळ तात्काळ ट्रान्सक्रिप्शनसाठी NVIDIA CUDA सपोर्ट
- **99 भाषा** — OpenAI Whisper च्या आधारे
- **हलका** — साधे C, Python नाही: डीमन, आणि सोबत फक्त libc शी लिंक केलेला 25 KB चा पर्यायी MCP सर्व्हर
- **सिस्टम ट्रे एकात्मता** — टास्कबारमध्ये अडथळा न आणणारा छोटा आयकॉन
- **Push-to-talk हॉटकी** — रेकॉर्ड करण्यासाठी `Ctrl+Shift+Space` (बदलता येणारी) दाबून ठेवा, सोडताच ट्रान्सक्रिप्ट कीबोर्ड कर्सरवर टाइप होतो
- **Push-to-talk-आणि-भाषांतर हॉटकी** — दुसरी, स्वतंत्रपणे कॉन्फिगर करता येणारी हॉटकी, जी शब्दशः ट्रान्सक्रिप्टऐवजी तुमच्या बोलण्याचे इंग्रजी भाषांतर टाइप करते
- **दुहेरी क्लिपबोर्ड** — मजकूर X11 च्या PRIMARY आणि CLIPBOARD या दोन्ही सिलेक्शन्समध्ये जातो
- **डेस्कटॉप नोटिफिकेशन्स** — ट्रान्सक्राइब झालेला मजकूर नोटिफिकेशनमध्ये दिसतो
- **व्हॉइस कमांड्स** — `commands/` मध्ये प्रत्येक भाषेसाठी एक कमांड फाइल, डिफॉल्टनुसार बंद (`OPONS_VOXD_COMMANDS=1`). नवी भाषा जोडण्यासाठी `commands/xx.txt` तयार करा, पुन्हा कंपाइल करण्याची गरज नाही.
- **क्षणिक नोटिफिकेशन्स** — डिफॉल्टनुसार नोटिफिकेशन्स दिसतात आणि मग पूर्णपणे नाहीशी होतात. `OPONS_VOXD_NOTIFY_PERSIST=1` त्यांना इतिहासात ठेवते.
- **नोटिफिकेशन मोड** — `OPONS_VOXD_NOTIFY=normal|quiet|silent|off` यशाची नोटिफिकेशन्स नियंत्रित करते (डिफॉल्ट `quiet`: बबल, आवाज नाही). त्रुटी मात्र नेहमी आवाजासह दिसतात, प्रत्येक मोडमध्ये, कोणत्याही अपवादाशिवाय. संपूर्ण तक्ता मुख्य README मध्ये आहे.
- **आपोआप कॅपिटलायझेशन** — वाक्यांचे पहिले अक्षर आपोआप कॅपिटल होते
- **गरजेनुसार GPU मोकळा करणे** — Whisper मॉडेल्स VRAM मधून अनलोड करा (ट्रे मेनूतून, किंवा बिल्ट-इन MCP सर्व्हरद्वारे कोणत्याही AI एजंटकडून) आणि काम झाल्यावर पुन्हा लोड करा
- **ऑटो-स्टार्ट** — लॉगिनच्या वेळी आपोआप सुरू होण्यासाठी कॉन्फिगर करता येते


```bash
ubuntu-drivers devices
sudo apt install nvidia-driver-590
sudo reboot
```

## लोकल AI साठी GPU मोकळा करणे (MCP सर्व्हर)

Whisper मॉडेल्स सतत GPU मेमरीत राहतात (`large-v3-turbo` + `medium` साठी सुमारे 3.8 GB). ती VRAM दुसऱ्या कामासाठी हवी असेल — लोकल LLM, इमेज मॉडेल, ट्रेनिंग रन — तेव्हा opons-voxd स्वतः बंद न होता ही मॉडेल्स अनलोड करू शकतो आणि नंतर पुन्हा लोड करू शकतो. अनलोड केल्याने प्रोसेसचा CUDA कॉन्टेक्स्टही नष्ट होतो, त्यामुळे opons-voxd `nvidia-smi` मधून पूर्णपणे गायब होतो (0 MB VRAM). मॉडेल फाइल्स अजून पेज कॅशमध्ये असतील तर पुन्हा लोड व्हायला एका सेकंदापेक्षा कमी वेळ लागतो, नाहीतर काही सेकंद.

**ट्रे आयकॉनच्या स्थिती:**

| आयकॉन | स्थिती |
|:---:|---|
| पांढरे वलय | मॉडेल्स लोड झालेली, तयार |
| लाल भरीव वर्तुळ | रेकॉर्डिंग |
| नारिंगी भरीव वर्तुळ | ट्रान्सक्रिप्शन सुरू |
| तिरकी रेघ असलेले राखाडी वलय (⊘) | मॉडेल्स अनलोड, GPU मेमरी मोकळी, डिक्टेशन बंद |
| निळा तीन-चतुर्थांश कंस | मॉडेल्स पुन्हा लोड होत आहेत |

मॉडेल्स अनलोड असताना आयकॉनवर क्लिक केल्यास किंवा push-to-talk हॉटकी दाबल्यास रेकॉर्डिंगऐवजी त्रुटीचे नोटिफिकेशन दिसते.

**हाताने:** ट्रे आयकॉनवर राइट-क्लिक > *Unload models (free GPU memory)* (मॉडेल्स अनलोड करा, GPU मेमरी मोकळी करा), मग *Reload models* (मॉडेल्स पुन्हा लोड करा).

**AI एजंटकडून (MCP):** डीमन `-m` / `--mcp` सह सुरू करा (डिफॉल्टनुसार बंद). `make` सोबत `opons-voxd-mcp` देखील तयार करते: stdio वर चालणारा, फक्त libc शी लिंक केलेला [Model Context Protocol](https://modelcontextprotocol.io) सर्व्हर (सुमारे 1.5 MB RAM). तो तीन टूल्स उपलब्ध करून देतो: `unload_models`, `reload_models` आणि `get_status`. Claude Code सह:

```bash
claude mcp add --scope user opons-voxd -- /path/to/opons-voxd/opons-voxd-mcp
```

इतर बहुतेक क्लायंट्स (Claude Desktop, Cursor, LM Studio...) हा JSON वापरतात:

```json
{ "mcpServers": { "opons-voxd": { "command": "/path/to/opons-voxd/opons-voxd-mcp" } } }
```

संपूर्ण तपशील [मुख्य README](../README.md#free-the-gpu-for-local-ai-mcp-server) मध्ये.

## Push-to-talk हॉटकी

सोबत येणारी `launch.sh` फाइल `ctrl+alt+w` (AZERTY साठी शिफारस केलेली) किंवा `ctrl+alt+z` (QWERTY साठी शिफारस केलेली) वापरते. ही की `A` च्या शेजारी आहे, त्यामुळे संपूर्ण कॉम्बिनेशन फक्त डाव्या हातानेच दाबता येते (करंगळी `Ctrl` वर, अंगठा `Alt` वर, अनामिका किंवा मधले बोट `W`/`Z` वर). टायपिंगची बैठक मोडावी लागत नाही, आणि बहुतेक डेस्कटॉप एन्व्हायर्न्मेंट्समध्ये हे कॉम्बिनेशन डिफॉल्टनुसार कोणत्याही कामाला जोडलेले नसते. ते `OPONS_VOXD_PTT_HOTKEY` ने कॉन्फिगर करा. संपूर्ण तपशील [मुख्य README](../README.md#push-to-talk-hotkey) मध्ये.
